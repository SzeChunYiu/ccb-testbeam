## Confirmed defect

Two reproducibility and provenance failures are possible.

1. **Destructive input aliasing.** A user may supply `--out` equal to `--sim` or `--reference`. The current invocation can finish from values already held in memory while destructively replacing the exact validated input bytes needed to reproduce it.
2. **Partial final artifact.** The final path is truncated as soon as it is opened. A later serialization, process, filesystem, or encoding failure can leave an incomplete CSV under the canonical requested output filename.

This is an artifact-integrity defect. It is independent of whether the stopping-power physics calculation is correct.

## Better method and acceptance contract

Registered policy:

`NO_INPUT_OUTPUT_ALIAS_AND_ATOMIC_REPORT_WRITE`

A complete remediation must:

1. resolve `sim_path`, `ref_path`, and `out_path` without requiring the output to exist;
2. reject output paths that alias either input, including resolved symlink equality where supported;
3. serialize the complete CSV to a temporary file in the output directory;
4. flush and close the temporary file successfully;
5. publish it through `os.replace(temp_path, out_path)` only after complete serialization;
6. remove the temporary file on failure and preserve any prior final report;
7. add direct CLI regressions for both input aliases and injected write failure;
8. record final output byte size and SHA-256 after publication.
