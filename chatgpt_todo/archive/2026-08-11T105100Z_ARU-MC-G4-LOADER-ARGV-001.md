## Mechanism universe

H1 — direct exec of the final HIBEAM executable with the historical argument spellings.

H2 — direct exec of the final executable, but with arbitrary/misleading `argv[0]` or later rewritten argument strings.

H3 — explicit glibc dynamic-linker invocation (`ld.so [loader options] PROGRAM [args...]`) that can inject loader-specific options independently of normal environment variables.

H4 — post-exec mutation of argv string bytes while executable identity stays unchanged.

H5 — `PR_SET_MM_ARG_START/END` relocation, changing what `/proc/<pid>/cmdline` exposes.

H6 — `/proc/<pid>/exe` redirection through `PR_SET_MM_EXE_FILE`, a separate residual mechanism that can invalidate a naive interpretation of the procfs executable link.

H2/H4/H5 are observationally equivalent with respect to a late stable cmdline snapshot when asking for historical `execve` argv; they are therefore collapsed into one unresolved historical-mutation class rather than counted as independent evidence.

## Authoritative external facts

Primary/authoritative references used:

- Linux man-pages `proc_pid_cmdline(5)`: running processes may overwrite argv strings, and procfs can be redirected to another argument-memory region through `PR_SET_MM_ARG_START`.
- Linux man-pages `PR_SET_MM_ARG_START(2const)` / related `PR_SET_MM` operations: the kernel memory-map descriptor fields controlling the command-line region can be changed subject to the operation's constraints.
- Linux man-pages `proc_pid_exe(5)` and `PR_SET_MM_EXE_FILE(2const)`: `/proc/<pid>/exe` identifies the executed command pathname in the ordinary case, but `PR_SET_MM_EXE_FILE` is a separate mutation mechanism.
- GNU C Library manual, Dynamic Linker Invocation: glibc supports explicit dynamic-linker execution with options before the target program, so environment capture alone cannot enumerate every loader-control input.

## Discriminating experiments executed

### Linux argv-rewrite control

A tiny C program was compiled locally and launched with arguments `alpha beta`. It overwrote the bytes backing its `argv[0]` with `MUTATED_ARGV0` and then slept. While alive:

- `/proc/<pid>/exe` still named the compiled program;
- `/proc/<pid>/cmdline` exposed `MUTATED_ARGV0\0alpha\0beta\0`.

This directly falsifies the immutable-`execve(argv)` interpretation. It is not a HIBEAM or detector test.

### Explicit glibc-loader control

A local process was launched as the glibc dynamic loader plus `/bin/sleep 3`. While alive:

- `/proc/<pid>/exe` resolved to the glibc loader;
- `/proc/<pid>/cmdline` contained the loader path, `/bin/sleep`, and `3`.

This discriminates ordinary explicit-loader invocation from direct target execution at the runtime-receipt boundary. It does not eliminate the separate `PR_SET_MM_EXE_FILE` mechanism.
