## Atomic defect

The first source-bound campaign implementation generated sensitivity grids directly into the tracked repository directory `geant4/single_stave/slurm/grids/` and only afterwards called the manifest creator, whose `require_clean_worktree()` rejects any tracked or untracked repository change.

That composition conflicts with the documented campaign contract: `generate_points.py` explicitly permits environment-controlled re-gridding (`CCB_GRID_*`), seed-replicate changes, event-count changes and other campaign choices. Any override that changes a tracked `points_*.csv` makes the repository dirty before the manifest is frozen, so the provenance gate rejects the very campaign variation whose bytes it is supposed to bind.

## Exact input/output contract

Let `C` be the exact clean superproject commit, `G_C` the committed grid generator at `C`, `E` the runtime campaign design inputs, and `P_k(E)` the generated points bytes for knob `k`.

Required source/output separation:

`SOURCE(C) = tracked repository bytes at exact C`

`ARTIFACT_k = P_k(E)`

`H_grid(k) = SHA256(P_k(E))`

`M = CanonicalManifest(C, H_link(C), execution_intent(E), {H_grid(k)})`

The source tree must remain clean while campaign artifact bytes are allowed to differ from repository baseline grids. A post-freeze change to `P_k` must fail the manifest/grid digest check. The manifest does not require `P_k(E)` to equal the repository's committed example grid.

## Competing mechanisms

1. **Generate into tracked source and require clean worktree.** Rejected: documented re-grid inputs necessarily dirty tracked `points_*.csv` before manifest creation.
2. **Drop the clean-worktree requirement.** Rejected: this would permit uncommitted source/helper mutations to masquerade as exact `superproject_commit` provenance.
3. **Ignore all grid changes in the clean-worktree check.** Rejected as unnecessarily subtle; path-ignore logic could hide source/config edits in the same directory and complicates the provenance trust boundary.
4. **Generate campaign grids outside the repository and hash the exact generated bytes.** Survives. Source bytes remain attributable to `C`; campaign-design outputs remain freely variable but content-bound.

## Deterministic falsifier

A temporary Git repository with a tracked `points_test.csv` was committed, then the file was modified as a documented-style re-grid. Exact command logic:

`git status --porcelain=v1 --untracked-files=all`

returned

` M geant4/single_stave/slurm/grids/points_test.csv`

and the pre-repair `require_clean_worktree` predicate therefore returned `FAIL_CLOSED`. No RNG, Geant4, ROOT, beam data or detector MC participated.

## Repair

On PR #1284:

- keep the committed generator at `geant4/single_stave/slurm/grids/generate_points.py` as source;
- generate campaign-specific grids into `${CCB_CAMPASSIGN_OUTDIR}/grids`;
- require `CCB_CAMPASSIGN_OUTDIR` to resolve outside the repository, preserving the strong all-files clean-worktree gate;
- build the campaign manifest from those external generated grid bytes;
- submit those same exact files to Slurm;
- analyze against the same campaign grid directory;
- add an integration regression with fake `sbatch` and an actual `CCB_GRID_PDE_SCALE="0.95 1.05"` override. The regression requires successful manifest creation, exact grid SHA-256 equality in the manifest, and byte-for-byte unchanged repository `git status` before/after.

## Invariants and limiting cases

- Default grids that happen to equal committed examples remain valid.
- A custom re-grid is valid if generated by the committed source checkout and its exact bytes are hashed into the manifest.
- A source-tree edit still fails closed.
- A campaign output directory inside the repository fails before submission; this keeps generated artifacts outside the source provenance domain.
- A post-submission grid mutation remains rejected by the existing per-task digest verifier.
